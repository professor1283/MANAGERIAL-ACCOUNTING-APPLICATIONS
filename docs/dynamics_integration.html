Microsoft Dynamics 365 / Dataverse Integration Guide

The application is fully functional with its packaged SQLite database. The included dynamics_adapter.py adds an optional synchronization layer for an organization's Microsoft Dataverse environment.

Important deployment distinction

Microsoft Dynamics 365 and Microsoft Dataverse are tenant-based cloud services. A downloadable package cannot contain a licensed Dynamics tenant or organizational credentials. A professor or system administrator must supply a Dataverse environment, register an application in Microsoft Entra ID, and grant the appropriate table permissions.

Configuration

  1. Create the custom Dataverse tables and columns described in dataverse_table_mapping.csv and data_dictionary.csv.
  2. Register an application in Microsoft Entra ID and grant it access to the Dataverse environment.
  3. Acquire an OAuth 2.0 access token for the organization URL.
  4. Set DATAVERSE_URL and DATAVERSE_ACCESS_TOKEN in the server environment.
  5. Use DataverseClient.create_row, update_row, and retrieve_rows from dynamics_adapter.py.
set DATAVERSE_URL=https://yourenvironment.crm.dynamics.com
set DATAVERSE_ACCESS_TOKEN=your_oauth_token
python server.py

Web API behavior implemented

The adapter sends authenticated OData requests to /api/data/v9.2/. It uses POST to create rows, PATCH to update rows, and GET to retrieve rows. Responses and synchronization status can be recorded in the local dynamics_sync_log table.

Security: Do not commit access tokens to the package. In a production deployment, use managed identities, Azure Key Vault, or a server-side OAuth token service. Use Microsoft Entra authentication for users whenever possible.
